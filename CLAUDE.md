# UNICEF Armenia — Образовательные модули для родителей

Проект: серия из **5 обучающих модулей** для родителей, опекунов и педагогов о цифровой
безопасности детей.

**Готовы все пять модулей:**

| № | Тема | Аудитории | Особенность |
|---|------|-----------|-------------|
| 1 | Ծնողական վերահսկողություն | одна | 13 гайдов с симулятором |
| 2 | Կիբեռբուլինգ | родители / педагоги | 3 таблицы, правовой блок |
| 3 | Թվային հիգիենա | родители / педагоги | 5 гайдов 2FA с симулятором |
| 4 | Առցանց սեռական շահագործում | родители / педагоги | 5 таблиц, тяжёлая тема |
| 5 | Թվային գրագիտություն և հետք | одна | 4 таблицы, настройки 9 платформ |

## Быстрый ввод в курс дела

**Где работаем:** `app/` — React + Vite приложение «SafeSteps». Всё остальное заморожено.
**Контент:** `app/src/data/module01.js` … `module05.js`. Все правятся **руками**:
генераторы модулей 2–5 одноразовые, см. ниже. Контакты помощи — общие,
в `data/help.js`. Реестр модулей — `data/modules.js`.
**Собрать:** `cd app && npm run build`. **Посмотреть:** `python3 -m http.server 8777` из корня → `/app/dist/`.

**Кто участвует:** Грайр (ведёт проект), Arman Zohrabyan (коллега-разработчик,
сделал React-приложение), Misha Tadevosyan (рецензент, автор 40 комментариев к документу).

**Два документа, без которых не понять задачу:**
- `source/comments-from-review.md` — 40 комментариев рецензента, это фактическое ТЗ на интерактив.
- `source/module-01-v2.txt` — новая версия текста модуля (сентябрь).

**Когда придёт новая версия документа:** просить у заказчика **`.docx`**, не Markdown —
Google Docs при экспорте в `.md` комментарии не переносит, они живут отдельным слоем.
Дальше `python3 source/extract-docx.py "путь/к/файлу.docx"` — положит рядом
комментарии с привязкой к тексту и чистый текст по абзацам.

**Главный блокер к показу:** в модуле 1 армянские тексты квиза, сценариев и части
формулировок писала модель — нужна вычитка носителем. Модуля 2 это не касается: он
собран из авторского текста и вычитан Грайром.

**Git:** коммиты делаются локально и **не отправляются** на GitHub без отдельной
просьбы Грайра. Коллега работает в том же репозитории.

⚠ **`source/` больше не в git.** Репозиторий публичный (D10), а там лежат
исходные документы заказчика и 40 комментариев рецензента с именем автора —
внутренняя переписка о качестве текста. Папка есть только на диске у Грайра,
в `.gitignore` вместе с `*.docx` и `*.pdf`. Коллега в репозитории её не увидит:
если материалы ему нужны, передавать напрямую.

### Как устроен симулятор гайдов (`guideSim.js` + `GuideSimulator.jsx`)

Сценарий **не пишется руками** — он выводится из тех же строк шагов, что и
текстовый список. Поэтому текст и симулятор не могут разойтись: правка
формулировки меняет обе подачи разом. Это критично перед вычиткой носителем.

Разбор строки вида `Settings › Family (рус. «Настройки › Семья»)`:

| Что в шаге | Что получается |
|------------|----------------|
| путь через `›` | экран меню, цель подсвечена рамкой |
| настройка без пути | экран с переключателем |
| нет названий настроек | карточка подтверждения «Կատարեցի» |

Значения (`Don't Allow`, `On`, `Off`) отфильтрованы — это выбор внутри экрана,
а не пункт меню. Не больше 3 экранов на шаг (`MAX_PER_STEP`), иначе плотные
шаги iOS разворачиваются в десяток подряд. Итого 92 экрана на 13 гайдов.

Соседние пункты меню — из пула `DECOY` по платформе, позиция цели
детерминирована хешем, дубликаты исключены.

**Внутри симулятора не должно быть движения.** Это выяснилось дорого: любая
анимация — въезд экрана, пульсация подсветки, разъезжающиеся точки прогресса —
внутри неподвижного корпуса читается как тряска, тем сильнее, чем чаще
нажимаешь (за гайд до 11 переходов). Сейчас: смена мгновенная, подсветка
статичная рамка, точки одной ширины. Не возвращать анимации без веской причины.

### Как устроен контент приложения (`app/src/data/module01.js`)

Структура другая, чем в замороженных прототипах. Модуль — это `M1.steps[]`,
каждый шаг = экран читалки, внутри `blocks[]`. У блока есть поле `k` — тип:

| `k` | Что это | Ключевые поля |
|-----|---------|----------------|
| `h` | заголовок | `text` |
| `p` | абзац | `text` |
| `list` | маркированный список | `items[]` |
| `note` | врезка с цветной полосой | `title`, `text` |
| `guide` | ★ пошаговый гайд (13 шт.) | `name`, `sub`, `steps[]` |
| `cards` | флеш-карточки (возрастные стадии) | `title`, `hint`, `fields[]`, `cards[]` |
| `pair` | две колонки ✓ / ✕ | `doTitle`, `dontTitle`, `doItems[]`, `dontItems[]` |
| `check` | чеклист с отметками | `items[]` |
| `links` | список ссылок | `items[]` |
| `figure` | иллюстрация с речевым облаком | `src`, `bubble`, `bubbleText`, `width`, `asideTitle` |

Внутри любой строки работает `((термин||пояснение))` — термин выделяется и
получает подсказку по наведению или фокусу (механика коллеги, класс `.ms-term`).
Требование рецензента №4–8; применено пока не везде.

Русские эквиваленты настроек в приложении вписаны **прямо в текст**:
`Settings › Family (рус. «Настройки › Семья»)`. Не как `[[en|ru]]` — та разметка
осталась в замороженных прототипах. Из этого же формата симулятор строит экраны.

⚠ **У карточки нет нижней строки.** Там были то «9 разделов · 13 гайдов»,
то «для родителей и педагогов» — у каждого модуля своё, и на одном экране это
читалось как бессистемный набор подписей. Поля `meta` и `time` убраны
(2026-10-05, Грайр). На карточке остаются только `kicker`, `title`,
`subtitle` и `blurb`.

`MODULES[]` — колода на экране выбора. У модуля 1 `ready: true`, у 2–5
`ready: false` и заголовок «Շուտով»: кнопка «начать» для них отключена,
чтобы не вести на пустую заглушку.

### Как устроен гейт в приложении (`app/src/moduleLogic.js`)

Правила D9 в одном файле, не размазаны по компонентам:

- `NEXT_STEP_BLOCKER` — флаг из `app/.env` (D17). При `false` все проверки
  ниже отвечают «можно», навигация и URL не блокируются
- `panelKeys(step)` — ключи гайдов шага; `openKeys(step)` — таблицы, пары, карточки
- `guidesSatisfied(s, step)` — раскрыт хотя бы один гайд (D16), или гайдов на шаге нет
- `canFinishReading(s, step)` — гайды удовлетворены и все прочие панели раскрыты
- `canAdvance(s, step)` — итоговое разрешение идти дальше (сейчас = `canFinishReading`,
  викторин нет — D17)
- `nextHint(s, step)` — **текст на заблокированной кнопке**: всегда объясняет,
  чего не хватает, а не просто гасит её
- `NAV_GROUPS` — группировка шагов в боковой навигации

Проверка стоит и **на навигации**: `ReaderPage` редиректит с незаработанной
секции на последнюю доступную, поэтому URL нельзя подобрать руками
(при выключенном флаге редиректа нет).

### Разметка внутри текстов контента — ТОЛЬКО в замороженных прототипах

⚠ Ниже — про `shared/module-01.js` и `concepts/`. В приложении формат другой,
см. раздел выше. Оставлено для случая, если понадобится заглянуть в архив.

В строках контента используется своя мини-разметка, чтобы каждый концепт мог подать
одно и то же по-своему:

| Маркер | Значение | Пример |
|--------|----------|--------|
| `[[English\|Русский]]` | Название настройки: оригинал + рус. эквивалент | `[[Screen Time\|Экранное время]]` |
| `**жирный**` | Смысловой акцент | |
| `{{n}}` | Ссылка на источник №n из `MODULE_01.sources` | `{{1}}` |

Каждый концепт реализует свою функцию `render(text)`:
- A — `Screen Time (рус. «Экранное время»)`, как в оригинале
- B — армянский текст, рус. подсказка по тапу
- C — моно-чип `Screen Time` + тултип
- D — только оригинал, рус. мелко под абзацем
- E — оригинал в тексте + названия появляются прямо на экране симулятора

## 3. Механика прохождения (D9) — замысел

⚠ Ниже описан **замысел** и то, как он был сделан в прототипах. Как это
реализовано в рабочем приложении — см. «Как устроен гейт в приложении» выше.

В E к этому набору добавляется пятый тип гейта — `sim`: шаг засчитан
только после действия в симуляторе (тап по нужному пункту меню или переключатель).

Модуль нельзя пролистать. Каждая страница открывает следующую только после **доказанного действия**.
Реализация различается по концептам, но набор проверок общий:

| Тип гейта | Что требуется | Зачем |
|-----------|---------------|-------|
| `read` | Долистать до конца страницы — маркер внизу должен попасть во вьюпорт | Нельзя нажать «Далее» не увидев текст |
| `expand` | Раскрыть все свёрнутые блоки на странице | Заставляет открыть каждый гайд, а не проскочить раздел |
| `check` | Отметить все пункты. **Чекбокс заблокирован, пока соответствующий блок не раскрыт** | Убивает сценарий «отметить всё автоматом» |
| `quiz` | Ответить правильно на контрольный вопрос | Проверка понимания, а не присутствия |

**Ключевое анти-чит правило:** отметка «выполнено» физически недоступна до раскрытия инструкции.
Порядок всегда: раскрыл → прочитал → отметил → открылась кнопка «Далее».

В прототипах у гайдов были две отметки — `Կատարված է` (сделано) и `Չի վերաբերում` (не применимо):
не у каждой семьи есть PlayStation. **В приложении отметок больше нет (D16):** ту же проблему
решает правило «достаточно раскрыть один гайд», а лишний клик на каждом гайде убран.
Неверный ответ в квизе сворачивает гайды шага, чтобы перечитать пришлось по-настоящему.

Кнопка «Далее» в заблокированном состоянии **всегда объясняет причину** («Մնաց 3 կետ», а не просто серая кнопка).
Пройденные шаги остаются доступны для возврата; непройденные — заблокированы, с иконкой замка.

⚠ Гейт `quiz` в приложении **временно не работает** — викторины убраны (D17).
Всю блокировку можно выключить флагом `VITE_NEXT_STEP_BLOCKER=false`.

Прогресс хранится в `localStorage`. При недоступном хранилище (iframe с жёсткими правилами)
модуль работает, но прогресс не переживает перезагрузку — это осознанный компромисс до появления бэкенда.

### A — «Ուղեցույց» / Справочник · строго UNICEF
- **Визуал:** UNICEF cyan `#1CABE2`, белый, тёмно-синий текст, Noto Sans Armenian. Официально, чисто, доверительно.

### B — «Ուղևորություն» / Путь · UNICEF-основа + вариация
- **Визуал:** UNICEF cyan + глубокий синий + тёплый коралловый акцент. Noto Serif Armenian в заголовках, Space Grotesk для чисел.
- **Структурный приём:** вертикальная маршрутная нить вместо полосы прогресса — видно, где ты и что впереди закрыто.
- **Логика:** остановки маршрута. Каждая — один экран, без длинной прокрутки.
- **Доказательство прохождения:** обязательный микро-вопрос на каждой остановке + выбор, который записывается в личный план.
- **Финал:** «Ձեր ընտանեկան պլանը» — персональный чеклист, собранный из ответов, готовый к печати.
- **Кому зайдёт:** тем, кому важна измеримая завершённость и ощущение курса.

### C — «Վահան» / Щит · собственный визуальный язык
- **Визуал:** тёмная сине-графитовая панель, янтарный и бирюзовый акценты, моноширинный шрифт для названий настроек. Инструмент, а не статья. Тёмная тема оправдана сценарием: родитель настраивает вечером, когда дети легли.
- **Структурный приём:** сначала собираешь свой дом из карточек устройств — дальше модуль показывает только твои гайды.
- **Логика:** страницы = разделы твоего набора. Пустые разделы пропускаются.
- **Доказательство прохождения:** каждый шаг гайда отмечается отдельно, не гайд целиком. Индикатор `Ձեր պաշտպանվածությունը: 62%`. Вместо теста — стресс-тест из 5 жизненных сценариев.
- **Кому зайдёт:** тем, кто ценит «сел и сделал прямо сейчас».

### D — «Զրույց» / Разговор · собственный визуальный язык
- **Визуал:** светлый холодно-белый фон, глубокий сливовый чернильный текст, фиолетовый и тиловый акценты. Крупный гротеск с широкими интерлиньяжами, без серифов. Сознательно уходит от «кремовой бумаги с терракотой».
- **Структурный приём:** возрастной слайдер 5 → 17 лет. Двигаешь — риски, фокус и инструменты перестраиваются под возраст твоего ребёнка.
- **Логика:** страницы-развороты. Чтобы открыть следующую, нужно применить слайдер к своему случаю.
- **Доказательство прохождения:** рефлексия «Ի՞նչ կասեիք» — выбираешь реплику родителя, получаешь разбор. Не тест на память, а тренировка реакции.
- **Кому зайдёт:** тем, для кого главное сообщение модуля — доверие, а не контроль.

### E — «Փորձարան» / Практикум · собственный визуальный язык · интерактивный симулятор
- **Визуал:** светлый холодный фон, градиент синий→бирюза, кольцевой прогресс, Manrope для латиницы. Ощущение современного приложения.
- **Структурный приём:** на экране — модель телефона с настоящим меню. Нужный пункт подсвечен и пульсирует; нажимаешь — экран уезжает и приходит следующий. Переключатели двигаются, счётчик растёт.
- **Почему анимация оправдана:** родители теряются не потому, что не понимают зачем, а потому, что не знают, **где** в настройках что лежит. Пройдя путь один раз на симуляторе, человек уже узнаёт его на своём устройстве.
- **Как строится:** шаг гайда разбирается автоматически — из разметки `[[English|Русский]]` извлекается путь. `Settings › Family` даёт экран «Settings» с целью «Family»; настройка без пути даёт экран с переключателем; шаг без настроек — карточку подтверждения. Окружающие пункты меню берутся из правдоподобного пула по платформе (`DECOY` в файле концепта).
- **Ограничение:** не больше 3 экранов на шаг (`MAX_PER_STEP`), иначе на плотных шагах iOS человек тапает по десятку экранов подряд. Полный текст шага виден всегда — теряется не информация, а лишние тапы.
- **Доказательство прохождения:** шаг засчитывается только после действия в симуляторе. Финальный тест из 8 вопросов, порог 70%.
- **Кому зайдёт:** если проблема аудитории не «не понимаю зачем», а «не знаю где».
- **Риск:** самый долгий по прохождению (~60 действий). Симуляция приблизительная, не точная копия интерфейсов — это надо честно проговорить со стейкхолдерами.

## 5. Технические правила

**Для приложения (`app/`):**
- Пути относительные (`base: './'`) и hash-роутинг — работает из `file://`, с подкаталога
  GitHub Pages и внутри iframe на чужом хосте (D2).
- Нет фиксированной `100vh` на внешнем контейнере; `100dvh` только на оболочке.
- `localStorage` может быть заблокирован в строгом iframe — в `store/progress.js`
  есть fallback в память: модуль работает, теряется только сохранение между перезагрузками.
- Гейт проверяется **на навигации**, а не только в интерфейсе: ссылка на незаработанную
  секцию редиректит на последнюю доступную.
- Уважать `prefers-reduced-motion`.

**Для замороженных прототипов (`concepts/`):**

- Никакой сборки, никаких зависимостей кроме Google Fonts. Открывается двойным кликом.
- Шрифты: `Noto Sans Armenian` / `Noto Serif Armenian` для армянского. Латиница — свой акцентный шрифт в каждом концепте. Обязательный системный fallback: `Mshtakan, Sylfaen, system-ui`.
- Прогресс/отметки — `localStorage`, ключ `unicef-m01-<concept>`. В iframe может быть заблокирован → оборачивать в `try/catch`, приложение должно работать и без него.
- Уважать `prefers-reduced-motion`: все анимации отключаются.
- Доступность: контраст не ниже AA, семантические заголовки, фокус виден, квиз проходится с клавиатуры.
- Никаких внешних картинок — только inline SVG и CSS. Материал должен работать офлайн и внутри iframe с жёстким CSP.
- Не использовать фиксированную высоту `100vh` для основного контейнера — сломается в iframe.

### Ссылки: гиперссылки живут отдельно от текста `.docx`

`extract-docx.py` вытаскивал текст и комментарии, но **не адреса ссылок** —
в Word они лежат в `word/_rels/document.xml.rels`, а в тексте остаётся только
подпись («Դիտել փոդքաստը», «internetmatters.org»). Из-за этого в приложении
долго был **один** живой URL при 62 в документе.

Достать их можно так:

```python
rels = ET.fromstring(z.read('word/_rels/document.xml.rels'))
m = {r.get('Id'): r.get('Target') for r in rels if r.get('TargetMode') == 'External'}
# в document.xml: <w:hyperlink r:id="rId7"> → m['rId7']
```

### Модули 2–5: текст перенесён генераторами

`source/modbuild.py` — общая библиотека (абзац по номеру, блоки, таблицы,
источники из гиперссылок), `source/build-moduleNN.py` — разметка конкретного
модуля. Запуск из корня: `python3 source/build-module03.py`.

⚠ **Генераторы ОДНОРАЗОВЫЕ.** Они перенесли текст из `.docx`; поверх легла
редакторская вычитка. Повторный запуск её затрёт. Если придёт новая версия
документа — генерировать в отдельный файл, сравнить и перенести правки.

Тексты взяты ДОСЛОВНО по номерам абзацев, вручную не перенабирались. Поэтому
модули 2–5 **не ждут вычитки носителем** — армянский в них авторский. Единственное
исключение в каждом модуле — вопрос в облаке у персонажа: явного «главного
вопроса», как в модуле 1, авторы не дали, он собран из подзаголовка.

Что проверять после сборки — полноту. Сверка по первым символам абзаца
обманывает: `**жирный**` и `((термины))` меняют начало строки. Сверять по
фрагменту из середины абзаца, предварительно сняв разметку с данных.

Повторы в данных — нормальны, если документ сам дублирует блок в обеих частях
(в модуле 3 это «признаки»): читатель видит только свою ветку.

### Модуль 2 «Կիբեռբուլինգ» — как устроен

**Тексты не перенабирались руками.** `app/src/data/module02.js` собран
скриптом прямо из `source/module-02.txt` по индексам абзацев. Поэтому — в
отличие от модуля 1, где модель писала квизы и пояснения, — армянский здесь
ровно такой, каким его написал автор, и **вычитки не ждёт**. Модель не
сочинила ни одной фразы.

Генератор — `source/build-module02.py` (локально, как и вся `source/`).
Запуск из корня: `python3 source/build-module02.py` — перезаписывает
`app/src/data/module02.js`. Принцип: `p(i)` берёт абзац по номеру,
`H/P/LIST/NOTE/TABLE/DID/TIP/PAIR/CHECK` заворачивают его в блок,
`STEP(label, title, role, blocks)` собирает шаг.

⚠ Разметка привязана к **номерам абзацев** текущего документа. Если заказчик
пришлёт новую версию, номера поедут: сначала перегенерировать текст
(`python3 source/extract-docx.py "…docx"`), затем сверить индексы в
`STEPS` — иначе в блоки попадут чужие абзацы. Полнота проверяется сверкой
текстов: каждый абзац документа должен найтись в собранном файле.

**Две аудитории (D19).** У шага есть поле `role`:

| `role` | Кто видит |
|--------|-----------|
| нет поля | все — введение, право, помощь, источники |
| `"parent"` | только родители (ՄԱՍ Ա) |
| `"teacher"` | только педагоги (ՄԱՍ Բ) |

Итого: родителю 10 шагов, педагогу 11. Роль выбирается на входе и меняется
кнопкой в шапке.

**Правовой раздел в документе повторён дважды** — в обеих частях, совпадая
на 71% и различаясь адресатом. В приложении он один общий шаг, взята полная
версия из части А (63 абзаца против 56). Дублировать незачем: читатель видит
свою ветку целиком, а закон один.

**Что должно быть в КАЖДОМ модуле.** Рецензент писал это про все модули
сразу, не только про первый — при добавлении модуля сверяться по списку:

| Требование | Как называется в коде |
|------------|------------------------|
| №1 персонаж с вопросом в начале | блок `figure` с `bubbleText` |
| №11 блок доп. информации под лампочкой | блок `tip` |
| №9 «Հետաքրքիր է» раскрывающимся окном | блок `did` |
| №4–8 термины с подсказкой | `((термин\|\|пояснение))` в тексте |
| №39 источники по наведению в конце | блок `sources` |
| №36, 37 кнопка помощи | экспорт `HELP…` + запись в `helpFor()` |
| №0 карточка модуля | строка в `MODULES[]`: `kicker`, `title`, `subtitle`, `blurb` |

⚠ **Контакты помощи у каждого модуля свои.** `HelpButton` получает их
пропом из `helpFor(moduleIndex)`; раньше он жёстко импортировал `HELP` из
модуля 1, и читатель модуля 2 про травлю видел телефоны из модуля про
родительский контроль. У модуля 2 первым идёт киберотдел полиции
(011 52 52 52), а не общий 102.

Чего в модуле 2 намеренно нет: `cards` (возрастные стадии — материал
модуля 1) и `guide` с симулятором (там нет путей по меню настроек;
инструкции по скриншотам — это сочетания клавиш, для них список честнее).

**Реестр модулей — `app/src/data/modules.js`.** Приложение писалось под один
модуль: `M1` был вшит в `moduleLogic` и страницы. Теперь всё, что зависит от
содержания, берётся оттуда: `moduleAt(i)`, `viewOf(mod, role)` (модуль с уже
отфильтрованными шагами), `scopeOf(i, role)`.

⚠ **Ключи прогресса теперь с областью:** `m0:шаг:блок`, `m1p:…`, `m1t:…`.
Без неё отметки двух модулей столкнулись бы на одинаковых «шаг:блок», а при
смене роли повисли бы на чужих блоках — состав шагов у родителя и педагога
разный. Версия стора поднята до 4, старый плоский прогресс модуля 1
переносится миграцией.

### Новые типы блоков

| `k` | Что это | Поля | В гейте D9 |
|-----|---------|------|------------|
| `did` | «Հետաքրքիր է» — раскрывающееся окно (№9) | `title`, `text`, `items[]` | нет |
| `tip` | доп. информация под лампочкой (№11) | `title`, `text`, `items[]` | нет |
| `sources` | источники, описание по наведению (№39) | `items[]` из `title`, `note`, `host`, `url` | нет |
| `table` | сравнительная таблица (модуль 2) | `title`, `head[]`, `rows[][]` | да, раскрытием |

Поля, которые меняют вид существующих блоков:

| Поле | Где | Что делает |
|------|-----|------------|
| `tone: "danger"` | `note` | красная врезка вместо голубой — для «чего НЕ делать» |
| `big: true` | `note` | заголовок крупным серифом: ключевое правило |
| `items[]` | `note` | список под текстом врезки |

Разметка внутри любой строки контента:

| Маркер | Что даёт |
|--------|----------|
| `((термин\|\|пояснение))` | подсказка по наведению и фокусу (№4–8) |
| `[подпись](адрес)` | ссылка; `tel:` набирает номер, веб открывается в новой вкладке |
| `[подпись](#help)` | **открывает панель помощи** — не дублировать контакты в тексте |
| `**жирный**` | зачин пункта: глаз цепляет, о чём пункт, до чтения целиком |

⚠ Разметка работает только в тексте блоков. В `title`, в заголовках `h` и
внутри таблиц она **не** рендерится — звёздочки и скобки покажутся как есть.

`table` на узком экране не скроллится вбок, а разбирается на карточки — по
карточке на признак. Горизонтальный скролл прятал бы половину сравнения за
краем экрана, а смысл таблицы именно в том, чтобы видеть колонки рядом.

`did` и `tip` намеренно вне гейта: факультативное углубление не должно
стопорить прохождение модуля. Оба сделаны на `<details>` — раскрытие
работает без JS и доступно с клавиатуры само по себе.

Механика `((термин||пояснение))` теперь применяется во **всех** текстовых
блоках, а не только во флеш-карточках, как было раньше.

### Как устроена кнопка помощи (`components/HelpButton.jsx`)

Данные — экспорт `HELP` в `data/module01.js`: `when[]` (в каких случаях
обращаться) и `contacts[]` (у каждого `tel` для набора и `label` как в
документе). Кнопка стоит **в шапке читалки**, а не плавающим углом: шапка не
скроллится, значит помощь доступна и в начале раздела, и в конце квиза, при
этом ничего не перекрывает — правый нижний угол занят кнопкой «Հաջորդ»,
левый нижний уехал бы под боковую навигацию.

Цвет `#D93A3A` выбран как единственное тёплое пятно в cyan-палитре — это и
есть «առանձին գույնով» из требования №36.

Escape в панели перехвачен на **фазе погружения** с `stopPropagation`: у
читалки свой слушатель на `window`, иначе один Escape закрывал бы и панель,
и весь модуль.

Контакты живут **только** в кнопке помощи (`HELP.contacts`). Раздел «Որտեղ դիմել»
из последнего шага удалён по просьбе Армана 2026-09-15 — дублировать
нечего, последний шаг теперь «Լրացուցիչ ընթերցանություն»: ссылки и источники.
Пятый контакт (Internet Matters) без телефона — вместо кнопки звонка только
ссылка на сайт.

### Состояние git и публикация

Всё отправлено на GitHub 2026-09-04. Правило прежнее: **новые коммиты
локальные, push только по отдельной просьбе Грайра.** Коллега работает в том

**Живая ссылка собирается сама.** `.github/workflows/pages.yml`: push в `main`
→ `npm run build` → деплой. Раньше Pages отдавал файлы прямо из репозитория,
поэтому живая ссылка застыла на сборке многомесячной давности и не отражала
код. Теперь пересобирается каждый раз.

**`app/dist/` лежит в git — и это осознанно.** Арман вернул его 15.09,
`.gitignore` закомментирован. Возражение было одно: два человека коммитят
минифицированные файлы → конфликт при слиянии, который руками не разрешить.
Грайр 28.09: **параллельно они не работают**, поэтому вопрос снят.

Что из этого следует на практике: при публикации `dist` из репозитория **не
используется** — workflow собирает заново из исходников. Значит на живой
ссылке всегда актуальная версия, даже если забыли пересобрать перед коммитом.
Расхождение `dist` с кодом в репозитории возможно и ни на что не влияет.
Проверить совпадение: `npm run build && git status --short app/dist` — пусто
значит сходится.

Публикуется не весь репозиторий, а только для показа: витрина, `concepts/`,
`shared/` и приложение. `CLAUDE.md` на сайт не идёт (проверено — 404).

| Адрес | Что там |
|-------|---------|
| `/` | витрина прототипов (архив) |
| `/app/dist/` | **приложение** — этот адрес уже разослан, не менять |

## 7. Структура контента Модуля 1 (каркас для всех 5 модулей)

Этот скелет повторяется в каждом модуле — на нём строится компонентная система:

1. **Обложка** — номер, заголовок, подзаголовок, дисклеймер
2. **Главный вопрос** — врезка, задающая проблему
3. **Цель** и **Целевая группа**
4. **Как пользоваться** — врезка-инструкция
5. **Теория** — таблица возрастных стадий, вызовы среды
6. **Практика** — пошаговые гайды, сгруппированные (ОС / соцсети / игры / мессенджеры)
7. **Чеклист** — сквозная последовательность действий
8. **Мягкая часть** — исследования, скрипты «что сказать / что не сказать», принципы
9. **Золотое правило** — ключевая врезка
10. **Экстренная помощь** — контакты
11. **Доп. материалы** — hy / ru
12. **Источники** — нумерованный список со ссылками
13. **Квиз** — формат зависит от выбранного концепта

Повторяющиеся типы блоков: `⚠ предупреждение`, `🔑 золотое правило`, `✓/✕ скрипты диалога`,
`пошаговый гайд`, `сравнительная таблица`, `чеклист`, `карточка контакта`.
